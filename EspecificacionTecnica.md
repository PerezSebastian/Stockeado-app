DOCUMENTO DE ESPECIFICACIÓN TÉCNICA (PRD) - GALAPE APP1. CONTEXTO Y VISIÓNGalape es una plataforma SaaS multi-tenant diseñada para que emprendedores gestionen su stock, ventas y tengan presencia online (landing page + catálogo + turnos) en un solo lugar.2. STACK TECNOLÓGICO (MANDATORIO)Framework: Next.js (Versión más reciente / App Router)Lenguaje: TypeScript (Tipado estricto)Base de Datos: MySQLORM: PrismaAutenticación: Auth.js (NextAuth v5)Validación de Datos: Zod + React Hook FormEstilos: Tailwind CSS + Shadcn/ui + Lucide ReactPagos (Suscripción): Mercado Pago SDK (Modelo de suscripciones recurrentes)3. ARQUITECTURA MULTI-TENANTEl sistema debe utilizar una única base de datos donde cada tabla crítica contenga un businessId.Rutas Administrativas: /dashboard/* (Protegidas por sesión y vinculadas al BusinessID del usuario).Rutas Públicas: /[slug] (Dinámicas). El sistema debe detectar el slug desde la URL para filtrar los productos y configuración visual del negocio correspondiente.Middleware: Implementar un middleware que gestione el flujo de peticiones y verifique la validez del slug o dominio.4. REQUISITOS DEL MVPA. Autenticación y UsuariosImplementar Auth.js con proveedor de Credenciales (Email/Password).Roles: ADMIN (acceso total) y VENDEDOR (acceso limitado a POS e Inventario, sin ver costos ni reportes).El registro de un nuevo usuario debe crear automáticamente una entidad Business.B. Gestión de Inventario (CRUD)Campos: Nombre, SKU, Categoría, Precio de Costo, Precio de Venta (en ARS), Stock Actual, Stock Mínimo.Trazabilidad: Cada cambio de stock debe generar un registro en la tabla StockMovement.Imágenes: Guardar archivos en el servidor local (VPS) y almacenar el path en la DB.C. Punto de Venta (POS)Buscador de productos por nombre/SKU.Carrito de compras funcional en cliente.Procesamiento de venta: Selección de método de pago y actualización atómica de stock.D. Landing Pages & TurnosMotor de renderizado dinámico en app/[slug]/page.tsx.El Admin puede elegir qué productos son "Públicos".Sistema de turnos básico: Definición de franjas horarias y formulario de reserva para clientes finales.5. MODELO DE DATOS (PRISMA SCHEMA - REFERENCIA)User: id, email, password, role, businessId.Business: id, name, slug, logoPath, planStatus (Active/Inactive), subscriptionId.Product: id, name, cost, price, stock, minStock, isPublic, businessId.Sale: id, total, paymentMethod, createdAt, businessId.Booking: id, clientName, dateTime, status, businessId.6. ESTRATEGIA DE PAGOS (MERCADO PAGO)Integración con el sistema de Suscripciones de Mercado Pago.Webhook para escuchar eventos subscription.created y subscription.updated.Bloqueo de acceso al /dashboard si la suscripción del Business está vencida.7. PAUTAS DE DESARROLLO PARA IA AGENTSServer Components: Priorizar Server Components para la obtención de datos.Server Actions: Usar Server Actions para todas las mutaciones (crear producto, vender, etc.).Zod: Todas las entradas de formularios deben ser validadas con esquemas de Zod antes de procesarse.Clean Code: Separar componentes UI de la lógica de negocio. Utilizar la carpeta components/ para UI y lib/ para utilidades/acciones.
